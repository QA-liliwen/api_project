# 单接口用例制作参考（xlsx 模板）

> 适用：平台「单接口用例」（测试项类型 1），按《自动化测试用例模板.xlsx》填写时对照查阅。
> 断言引擎：`api_app/api_test/run_request.py`；落库校验：`api_app/api_test/sql_assert.py`。

---

## 一、单接口执行逻辑（一条用例进来后发生什么）

```
xlsx 行  →  平台解析(按;拆断言)  →  合并域名/环境/Token/头模板  →  pytest 逐条执行
                                                              │
                                            ┌─────────────────┴─────────────────┐
                                            │ 1. is_active != 'Y' → 跳过本条      │
                                            │ 2. 发请求(GET body拼URL / POST json)│
                                            │ 3. 状态码断言（最先执行，失败即停）   │
                                            │ 4. 响应必须是 JSON，否则直接报错     │
                                            │ 5. 按断言列【书写顺序】逐条执行      │
                                            │    任一条失败 → 本条用例失败，       │
                                            │    后续断言不再执行                 │
                                            │ 6. set: 提取的变量存入本条用例       │
                                            │    独立变量池，供本条 sql: 的        │
                                            │    ${var} 引用（跨用例不共享）      │
                                            └───────────────────────────────────┘
```

**要点**

- 请求头不在 xlsx 里写：域名、环境、Token、头模板由运行配置（页面选择）统一注入。
- 每条用例的变量池是**独立的**：CASE_001 里 `set:` 的变量，CASE_002 用不了。
- 断言列按书写顺序执行，`set:` 必须写在引用它的 `sql:` **前面**。
- 跳过≠通过：`is_active` 不为 Y 的用例在报告里是 skipped，不计失败。

---

## 二、xlsx 模板列说明

表头必须一字不差（第 1 行）：`CaseID | 用例名称 | 是否执行 | 请求体 | 预期状态码 | 断言 | 描述`

| 列名 | 必填 | 填写规则 |
|---|---|---|
| CaseID | 建议 | 用例编号，报告中显示用；多个测试项合并跑时建议全局唯一 |
| 用例名称 | 建议 | 如「单选题正常预览」 |
| 是否执行 | 是 | 填 `Y` 才执行，其他值跳过 |
| 请求体 | 视接口 | POST：填完整 JSON（`{...}` 开头结尾会被解析成 JSON 对象并校验）；GET：填 `a=1&b=2` 形式，原样拼到 URL 问号后；无 body 留空 |
| 预期状态码 | 是 | 数字，如 `200`；**每条用例固定先断言它**，为空则整表解析失败 |
| 断言 | 是 | 多条断言用**英文分号 `;` 分隔**（见下节全集）；为空则整表解析失败 |
| 描述 | 否 | 备注、前置条件等 |

## 三、取值路径语法

所有断言里的路径都用**斜杠分层**，数字段表示数组下标：

| 响应 JSON | 路径写法 |
|---|---|
| `{"message":"success"}` | `/message` |
| `{"data":{"id":5}}` | `/data/id` |
| `{"data":[{"id":5}]}` | `/data/0/id` |
| `{"data":{"items":[{"ids":["C"]}]}}` | `/data/items/0/ids/0` → `"C"` |

- 路径不存在 → 该条断言失败（写路径时先用工具实际响应核对一遍）。
- `sql:` 断言里的路径作用在**请求体**上（不是响应体），取路径最后一段作为列名去查询结果里取值（详见 4.8）。

## 四、断言方法全集

### 4.1 数据断言（默认，无前缀）

格式：`路径 运算符 预期值`，如 `/code=0`

| 运算符 | 含义 | 说明 |
|---|---|---|
| `=` / `==` | 相等 | 两者等价 |
| `!=` | 不等 | |
| `>` `<` `>=` `<=` | 数值比较 | 两侧先转 float，**预期值必须能转成数字** |

例：`/data/total>=1`、`/message==success`、`/data/list/0/name=单选题`

### 4.2 数组长度断言 `len:`

格式：`len:路径 运算符 数字`

例：`len:/data/list>=1`（列表至少 1 条）、`len:/data/items=4`（恰好 4 个选项）

- 先按路径取到数组，再取 `len` 与数字比较；路径取到的不是数组会报错。
- 只支持数值比较（`> < >= <= = == !=`），预期值必须是整数。

### 4.3 存在性断言 `exists:`

格式：`exists:路径`

例：`exists:/data/id`、`exists:/data/0/solution/choiceSolution/ids`

- 只要路径**能取到值**即通过（不关心值是什么）；字段不存在即失败。
- 适合校验「关键字段必须返回」。

### 4.4 数据结构断言 `type:`

格式：`type:路径=类型名`

| 类型名 | 对应 JSON |
|---|---|
| `list` | 数组 `[]` |
| `dict` | 对象 `{}` |
| `str` | 字符串 |
| `int` | 整数 |
| `float` | 浮点 |
| `bool` | `true`/`false` |
| `none` | `null` |

例：`type:/data=list`（data 必须是数组）

### 4.5 响应头断言 `header:`

格式：`header:头名=预期值`

例：`header:Content-Type=application/json`

- 头名大小写不敏感。
- 用 `=` 比较时若实际值带参数后缀（如 `application/json;charset=UTF-8`），会自动按 `;` 截断再比一次，写基础值即可。

### 4.6 成员断言 `in:`

格式：`in:路径=候选1|候选2|候选3`（候选列表用**竖线 `|`** 分隔）

例：`in:/data/0/questionType=single|multiple|judge`

- 语义：实际值**属于**候选列表之一即通过（"或"关系）。
- 候选值逐个做类型转换（见第五节），写 `'1'` 会按字符串 1 比，写 `1` 按数字比——与实际值类型对齐即可。

### 4.7 变量提取 `set:`（不是断言，是取数动作）

格式：`set:变量名=响应路径`

例：`set:qid=/data/id`

- 从**响应**里按路径取值，存入本条用例的独立变量池。
- 唯一用途：供本条用例后面的 `sql:` 断言用 `${qid}` 拼进 SQL（WHERE 条件）。
- 提取路径不存在 → 用例失败。
- 常见错误：`sql:` 写在 `set:` 之前 → 报「SQL 变量未定义: xxx」。

### 4.8 SQL 落库校验 `sql:`（查库 + 比入参）

格式（三段式）：

```
sql:SELECT 列 FROM 表 WHERE 条件=/请求体路径=预期值      ← 三方校验（有预期值）
sql:SELECT 列 FROM 表 WHERE 条件=/请求体路径            ← 两方校验（省略预期值）
```

**工作方式**

1. 先执行查询，结果包装成 `{rows:[...], row_count:N}`；
2. 断言路径作用于**请求体**：按路径从入参 JSON 里取值；
3. 查询结果里取哪个列？取**断言路径最后一段**当列名（如路径 `/questions/0/solution` → 找查询结果里的 `solution` 列）：
   - 结果里有同名列 → 取该列（第一行）；
   - 没有同名列但只查了一列 → 自动取这唯一一列（单列兜底）；
   - 多列又没同名列 → 报错，**用 `as` 别名对齐**（如 `SELECT answer AS solution ...`）；
4. 三方校验：入参值、查库值**都**与预期值比较；两方校验：查库值与入参值直接比对；
5. 查询结果为空 → 直接报错（WHERE 没命中数据）。

**`= / ==` 比较带 JSON 归一化**：库里常把 JSON 存成字符串（如 `{"ids":["D"]}`），入参是结构化对象，此时会自动解析后按结构深度比较，空格/键顺序差异不造成影响。其他运算符（`!= > < >= <=`）是直比，不做过解析。

**变量**：SQL 里可写 `${变量名}`，值来自本条用例前面 `set:` 提取的变量；未定义直接报错。

**两个前置配置（缺一即跳过，不报错）**

| 配置 | 位置 | 作用 |
|---|---|---|
| SQL 库名 | 测试项编辑页的「SQL 库名」字段 | 指定查哪个库；为空 → 所有 sql: 跳过 |
| 连接四要素 | 平台按**域名**（如 devapi1.lingshi.com）关联 DB_SqlEnv 记录 | host/port/user/password；未配置 → 所有 sql: 跳过 |

**书写限制（引擎强校验）**

- SQL 只允许 `SELECT` / `WITH` 开头；
- **SQL 体内禁止分号**（分号是断言分隔符，别想着写多条语句）；
- 请求体必须是 JSON 对象——GET 接口（body 是字符串）上用 `sql:` 会报「入参不是JSON对象」。

**实例**（存题后校验落库，答案入库为 JSON 字符串时归一化比较也能过）：

```
set:qid=/data/questionId;sql:SELECT solution FROM exam_question WHERE id=${qid}=/questions/0/solution
```

## 五、预期值的类型规则（两层解析）

断言里的预期值按下表自动转类型（引号规则是所有断言共用的）：

| 写法 | 解析结果 | 说明 |
|---|---|---|
| `'success'` / `"success"` | 字符串 `success` | **引号包裹 = 强制字符串**，跳过一切类型转换 |
| `true` / `false`（大小写都行） | 布尔值 | 引号 `'true'` 才是字符串"true" |
| `null` / `none` | 空值 | |
| `1` / `2.5` | 数字 | 先按 int 试再按 float |
| 其他（如 `success`、中文） | 原样字符串 | |

- 响应里 `"code":0` 是数字 → 写 `/code=0`（别写成 `/code='0'`，那是字符串 0，不相等）。
- 响应里 `"enabled":"true"` 是字符串 → 写 `/enabled='true'`（带引号），写 `true` 反而比不过。

## 六、完整实例

### 实例 1：题目预览接口（真实用例，五个断言类型齐套）

| 列 | 内容 |
|---|---|
| CaseID | CASE_001 |
| 用例名称 | 单选题正常预览 |
| 是否执行 | Y |
| 请求体 | `{"questions":[{"questionTypeId":1,"title":[{"type":"TEXT","content":"What fell that night?"}],"choices":[...],"answers":[1]}]}` |
| 预期状态码 | 200 |
| 断言 | `/message=='success';len:/data/0/content/choice/items>=4;exists:/data/0/solution/choiceSolution/ids;type:/data=list;header:Content-Type=application/json;in:/data/0/questionType=single|multiple|judge` |
| 描述 | 校验预览成功、选项≥4、答案字段存在、data 为数组、题型枚举合法 |

断言逐条读：① message 等于字符串 success → ② 选项数组至少 4 项 → ③ 答案字段存在 → ④ data 是数组 → ⑤ 响应头正确 → ⑥ questionType 只能是三种之一。

### 实例 2：建卷 + 存题 + 落库校验（领导录制脚本那套业务）

| 列 | 内容（存题接口用例） |
|---|---|
| CaseID | CASE_SAVE_001 |
| 用例名称 | 新建单选题并落库校验 |
| 是否执行 | Y |
| 请求体 | `{"examId":123,"questionId":0,"questionType":"single","content":{"stem":"<p>新建单选题题干</p>","choice":{"items":[{"id":"A","item":"<p>q</p>"},{"id":"B","item":"<p>w</p>"},{"id":"C","item":"<p>e</p>"},{"id":"D","item":"<p>r</p>"}]}},"solution":{"choiceSolution":{"ids":["C"]}}}` |
| 预期状态码 | 200 |
| 断言 | `/code=0;set:qid=/data/questionId;sql:SELECT solution FROM exam_question WHERE id=${qid}=/solution/choiceSolution` |
| 描述 | 保存成功 → 从响应提取新题 ID → 查库比对 solution 与入参一致（两方校验，库内 JSON 字符串自动归一化） |

若想再卡一道预期值（三方校验），把最后一条改成：

```
sql:SELECT solution FROM exam_question WHERE id=${qid}=/solution/choiceSolution={"choiceSolution":{"ids":["C"]}}
```

### 断言组合顺序建议

```
状态码（自动）→ 业务码(/code=0) → 关键字段存在(exists:) → 数据断言/长度/成员
→ set:提取 → sql:落库校验
```

把 `set:`/`sql:` 放最后：接口都还没验通就查库，失败信息会看不懂是存错了还是查错了。

## 七、常见坑速查

| 现象 | 原因 |
|---|---|
| 整表解析失败（提示某行为空） | 预期状态码或断言列有空行/空值 |
| 断言没被拆开，整条报「格式错误」 | 用了中文分号 `；`，必须是英文 `;` |
| 字符串比较死活不过 | 数字/布尔没加引号，或字符串加了多余引号（对照第五节类型表） |
| 报「SQL 变量未定义」 | `sql:` 写在了 `set:` 前面 |
| sql: 断言悄悄不执行 | 测试项没配 SQL 库名，或当前域名没配 DB_SqlEnv（看运行日志有"跳过"提示） |
| 报「SQL安全校验失败」 | SQL 不是 SELECT/WITH 开头，或体内有分号 |
| 报「查询结果不存在字段 xx」 | 查多列且列名与入参路径最后一段对不上，加 `as` 别名 |
| 数值比较报 float 转换错误 | 预期值写成了非数字（如 `/data/count>=abc`） |
| GET 用例 sql: 报「入参不是JSON对象」 | GET 的请求体是 query 字符串，做不了入参路径比对 |
| 响应非 JSON | 接口没返回 JSON，resp.json() 直接抛错，用例判红 |
