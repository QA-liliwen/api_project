## 一、制作流程

1. 复制《自动化测试用例模板.xlsx》。
2. 每一行填写一条测试用例。
3. 在平台上传 xlsx，并选择域名、环境和测试角色。
4. 执行测试，在运行记录中查看日志和报告。

平台会自动补齐请求地址、环境、Token 和请求头，xlsx 中不需要填写这些内容。

---

## 二、Excel 怎么填

第 1 行表头必须保持不变：

| CaseID | 用例名称 | 是否执行 | 请求体 | 预期状态码 | 断言 | 描述 |
|---|---|---|---|---|---|---|

各列填写规则：

| 列名     | 必填  | 怎么填                         | 示例                         |
| ------ | --- | --------------------------- | -------------------------- |
| CaseID | 否   | 用例编号，建议唯一                   | `CASE_001`                 |
| 用例名称   | 否   | 简要描述测试目的                    | `正常查询列表`                   |
| 是否执行   | 是   | 填 `Y` 执行，其他值跳过              | `Y`                        |
| 请求体    | 否   | POST 填 JSON；GET 填查询参数；无参数留空 | `{"page":1}`               |
| 预期状态码  | 是   | 先于业务断言执行                    | `200`                      |
| 断言     | 是   | 多条用英文分号 `;` 分隔              | `/code=0;/message=success` |
| 描述     | 否   | 可选，填写场景或前置条件                | `校验正常返回`                   |

### 请求体填写方式

**POST/PUT 接口：填写完整 JSON**

```json
{"page":1,"pageSize":20,"keyword":"测试"}
```

**GET 接口：填写查询参数，不要加问号**

```text
page=1&pageSize=20
```

**无请求参数：留空即可。**

## 三、最常用的断言

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 2,
    "items": [
      {"id": 101, "name": "测试数据"}
    ]
  }
}
```

取值路径用 `/` 分层，数组下标直接写数字：

| 想取的值 | 路径 |
|---|---|
| `code` | `/code` |
| `data.total` | `/data/total` |
| 第一条数据的 id | `/data/items/0/id` |

### 断言速查

| 用途   | 写法              | 示例                                     |
| ---- | --------------- | -------------------------------------- |
| 相等   | `路径=预期值`        | `/code=0`                              |
| 不等   | `路径!=预期值`       | `/message!=error`                      |
| 数值比较 | `> < >= <=`     | `/data/total>=1`                       |
| 数组长度 | `len:路径 运算符 数字` | `len:/data/items>=1`                   |
| 字段存在 | `exists:路径`     | `exists:/data/items/0/id`              |
| 类型校验 | `type:路径=类型`    | `type:/data/items=list`                |
| 响应头  | `header:头名=预期值` | `header:Content-Type=application/json` |
| 成员校验 | `in:路径=值1\|值2`  | `in:/data/status=0\|1`                 |

支持的类型名：`list`、`dict`、`str`、`int`、`float`、`bool`、`none`。

多条断言必须使用**英文分号**连接：

```text
/code=0;/message=success;len:/data/items>=1;exists:/data/items/0/id
```

推荐顺序：

```text
业务码 → 关键字段存在 → 数据值/长度/类型 → 变量提取 → SQL校验
```

## 四、预期值怎么写

| 写法 | 实际类型 |
|---|---|
| `0`、`2.5` | 数字 |
| `true`、`false` | 布尔值 |
| `null`、`none` | 空值 |
| `success`、`测试` | 字符串 |
| `'0'`、`'true'` | 强制按字符串比较 |

注意实际返回值的类型：

```text
响应是数字 0     → /code=0
响应是字符串 "0" → /code='0'
响应是布尔 true  → /enabled=true
响应是字符串 "true" → /enabled='true'
```

## 五、需要校验数据库时

普通用例不需要这一部分。只有接口执行后需要检查数据是否落库时，才使用 `set:` 和 `sql:`。

### 第一步：从响应提取变量

```text
set:qid=/data/questionId
```

表示把响应中的 `questionId` 保存为变量 `qid`。

### 第二步：使用变量查询数据库

```text
sql:SELECT solution FROM exam_question WHERE id=${qid}=/questions/0/solution
```

表示：

1. 使用 `${qid}` 查询数据库；
2. 读取请求体中的 `/questions/0/solution`；
3. 比较数据库值与请求体值是否一致。

完整写法：

```text
/code=0;set:qid=/data/questionId;sql:SELECT solution FROM exam_question WHERE id=${qid}=/questions/0/solution
```

关键限制：

- `set:` 必须写在使用变量的 `sql:` 前面；
- SQL 只允许以 `SELECT` 或 `WITH` 开头；
- SQL 内容中不能出现分号；
- 测试项必须配置“SQL 库名”；
- 当前域名必须配置数据库连接；
- GET 请求体不是 JSON，不适合做这种入参与数据库值比较。

## 六、完整示例

| CaseID | 用例名称 | 是否执行 | 请求体 | 预期状态码 | 断言 | 描述 |
|---|---|---|---|---|---|---|
| CASE_001 | 正常查询列表 | Y | `{"page":1,"pageSize":20}` | 200 | `/code=0;/message=success;type:/data/items=list` | 校验正常返回 |
| CASE_002 | 列表至少有一条数据 | Y | `{"page":1,"pageSize":20}` | 200 | `/code=0;len:/data/items>=1;exists:/data/items/0/id` | 校验列表数据 |
| CASE_003 | 非法页码 | Y | `{"page":-1,"pageSize":20}` | 200 | `/code!=0` | 校验异常参数处理 |
| CASE_004 | 暂不执行 | N | `{"page":1}` | 200 | `/code=0` | 报告中显示 skipped |

## 七、常见问题

| 问题 | 处理方法 |
|---|---|
| 整个表格解析失败 | 检查“预期状态码”和“断言”是否有空值 |
| 多条断言没有拆开 | 把中文分号 `；` 改成英文分号 `;` |
| 路径取值失败 | 用真实响应确认层级和数组下标 |
| 字符串比较失败 | 检查实际值是数字、布尔还是字符串 |
| 用例被跳过 | “是否执行”必须填写 `Y` |
| SQL 变量未定义 | 把 `set:` 放到 `sql:` 前面 |
| SQL 没有执行 | 检查 SQL 库名和数据库连接配置 |
| 响应不是 JSON | 当前框架只能对 JSON 响应执行内容断言 |
